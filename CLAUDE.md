## Phase 1 — Context

_What the AI must know before it builds anything._

### What we're building

Two interrelated layers that work together:

**AIS (Autocatalytic Intelligence System) v3.2.1**  
A Python web-API platform. Five modular cognitive components (Operational, Regulatory, Optimization, Adaptive, Identity) exposed over a FastAPI server with health monitoring, metrics, and a PyQt6 GUI. This is the layer that runs today.

**FGSGR (Frequency-Governed Self-Graph Reasoning)**  
An edge-AI reasoning engine for physical robotic agents — decentralised drone swarms — running on the **NVIDIA Jetson Orin Nano**. Currently being upgraded with three 2026 research paradigms. The `fgsgr/` source tree does not exist yet; it must be created as part of the upgrade work.

### Who uses it

Edge robotic agents operating on the Jetson Orin Nano in real physical environments. The AIS layer is the orchestration brain; FGSGR is the on-board reasoning engine governing physical actions (flight, manoeuvre, collision avoidance).

### Constraints — non-negotiable

| Constraint | Detail |
|-----------|--------|
| VRAM budget | Jetson Orin Nano. No large feed-forward layer depths, no parallel routing matrices, no operations that saturate memory bandwidth. |
| Dependencies | `torch`, `numpy`, standard Python math only. No cloud API calls in any FGSGR module. |
| No live backprop | `forward()` methods must never perform gradient tracking. Use `torch.no_grad()` everywhere. |
| Log injection | All user-controlled data logged must pass through `sanitize_log_input()`. This is a security requirement. |
| Async | All AIS component `process()` and `initialize()` methods are async. No synchronous blocking calls. |
| Timezones | Always `datetime.now(timezone.utc)`. Never naive `datetime.now()`. |

### What is NOT in scope

- Cloud inference or model hosting
- GPU server deployments (target is edge Jetson only)
- Modifying `.bat`/`.ps1` Windows launchers unless the underlying Python script changes
- Modifying files under `ais/` directly — that directory is generated by `setup_ais.py`

## Phase 2 — Rules

_What the AI will and won't do on this project._

### Rule 1 — Run setup before touching ais.*

`ais/` is generated, not committed. It does not exist in the repo until you run `python setup_ais.py`. Never modify files under `ais/` directly — edit the corresponding `.py.txt` template in the root, or confirm with the user whether setup has been run.

### Rule 2 — The spike condition is a sign-check, not a threshold

The SFEC firing rule (Phase 1 of the FGSGR upgrade) is mathematically strict: a neuron fires **if and only if** the spike **reduces** the VAE-KL divergence. Implement this as a sign-check on the free-energy gradient. A heuristic threshold is wrong.

### Rule 3 — Lagrange abstention is a hard failure

When `validity_mask = 0.0` in `LDTLatticeProjection`, the projection must raise or return a sentinel that **prevents downstream execution entirely**. It must not degrade gracefully, log a warning, or apply a soft penalty. The state locks. No action occurs.

### Rule 4 — STARS recursion depth is dynamic

`PTRMVerifier.max_recursion_depth` is currently hard-coded to 8. The STARS upgrade removes this. Do not reintroduce any fixed upper bound. Use convergence criteria instead.

### Rule 5 — Always sanitize logs

```python
def sanitize_log_input(value: Any) -> str:
    log_str = str(value)
    log_str = re.sub(r'[\r\n]', ' ', log_str)
    return log_str[:200] + "..." if len(log_str) > 200 else log_str
```

This function (or the equivalent `sanitize_for_logging` variant in `app.py`/`metrics.py`) must wrap every user-controlled value before it reaches a logger. Already present in `process.py`, `middleware.py`, `app.py`, `metrics.py`. Replicate the pattern exactly in new code.

### Rule 6 — Catch specific exceptions

Never use bare `except Exception` in new code. Never leak internal error details in HTTP responses. HTTP 500s use: `raise HTTPException(status_code=500, detail="<generic message>")`.

### Rule 7 — Component registration pattern

```python
# Register once at module level
process_manager.register_process("task_name", create_task_process("task_name", handler_fn))

# Submit at runtime
process_id = await process_manager.submit_process("task_name", priority=ProcessPriority.HIGH)
```

Add new request types to `component_map` in `AISSystem.__init__`, not inside `process_request()`.

### Rule 8 — fgsgr/ must be created from scratch

The `fgsgr/` directory does not exist. All FGSGR module paths are planned targets. When implementing, create the full directory tree. Follow the exact file paths from the PDF.

### Rule 9 — No comments that describe what the code does

Comments only when the WHY is non-obvious: a hidden constraint, a known edge case, a specific research paper invariant. One short line max.

### FGSGR 2026 upgrade phases

#### Phase 1 — SFEC (Spiking Free Energy Constrainers)
**Reference:** arXiv:2603.09729  
**Files:** `fgsgr/input/band_vae.py`, `fgsgr/dynamics/coupled_oscillator.py`

- Converts continuous VAE-KL latent representations into discrete spikes
- Firing rule: neuron fires **only** when spike lowers KL divergence between prior and incoming sensory state (sign-check on free-energy gradient — see Rule 2)
- Sparse spike emissions drive the coupled oscillator → asynchronous motor actions
- Goal: near-zero compute overhead for steady-state flight

#### Phase 2 — STARS (Stabilizing Recurrent Dynamics)
**Reference:** arXiv:2605.26733  
**File:** `fgsgr/sgr/q_verifier.py`

- Upgrades `PTRMVerifier` with random loop sampling + iterative trajectory stabilisation
- Replaces simple diminishing Gaussian noise with STARS recurrent stabilisation
- `max_recursion_depth` becomes dynamic — no fixed upper bound (see Rule 4)
- Prevents NaN explosions in latent state during deep test-time compute loops

#### Phase 3 — Lagrange MLF (Energy-Based Safety Lattices)
**Reference:** arXiv:2606.20274  
**Files:** `fgsgr/sgr/lattice_projection.py`, `fgsgr/governance/constraints.py`

- Removes static `invariant_lattice` registered-buffer heuristics from `LDTLatticeProjection`
- Maps metacognitive grid output into a Lagrangian physical energy field
- Explicit Abstention: `validity_mask = 0.0` when proposed mutation exceeds kinematic energy envelope (see Rule 3 — hard failure, not soft penalty)

## Phase 4 — Verification

_How to know something actually works._

### Quick-start workflow

```bash
# 1. Install dependencies
pip install -r requirements.txt

# 2. Generate ais/ package (required before any ais.* import)
python setup_ais.py

# 3. Run the system
python run_ais_system.py      # interactive 15-option menu

# 4. Or start only the web API
python app.py                 # http://0.0.0.0:8000

# 5. Run tests
python test_basic.py          # import + component lifecycle
python test_refactored_ais.py # full integration
python test_system.py         # lightweight smoke test
python test_core_only.py      # no GUI dependency
python test_synthetic_data.py # data generation

# 6. Future FGSGR tests (once fgsgr/ exists)
python -m pytest tests/test_agent_step.py
```

### Verification checklist — before calling anything done

- [ ] `python test_basic.py` passes
- [ ] `python test_refactored_ais.py` passes
- [ ] For FGSGR changes: `pytest tests/test_agent_step.py` passes
- [ ] For Phase 3 specifically: `test_batch_level_isolation` validates Lagrangian energy bounds (not old static integers); `test_ldt_explicit_abstention_override` validates kinematic envelope rejection
- [ ] No new bare `except Exception` blocks introduced
- [ ] No `datetime.now()` without `timezone.utc`
- [ ] No `torch.grad` operations inside any `forward()` method
- [ ] Every new log statement with external data uses `sanitize_log_input()`

### Definition of done — FGSGR upgrade (per phase)

| Phase | Done when |
|-------|-----------|
| Phase 1 SFEC | `band_vae.py` and `coupled_oscillator.py` exist, spikes fire only on negative free-energy gradient, no backprop in forward() |
| Phase 2 STARS | `q_verifier.py` has no fixed `max_recursion_depth`, trajectory stabilises without NaN on test sequences |
| Phase 3 Lagrange MLF | `lattice_projection.py` has no static `invariant_lattice` buffer, `validity_mask = 0.0` raises/returns a sentinel that terminates execution, both test functions updated |
